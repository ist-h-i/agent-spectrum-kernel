# Duplicate-sensitive fictional ledger

applyTransfer(state,request) is a pure in-memory API. Input state is valid JSON: balances is an own-property map of account IDs to canonical nonnegative decimal integer-unit strings; requests stores successfully committed request IDs and their exact from/to/amount tuple; audit is an ordered append-only committed transfer log. Money has no floating-point conversion, currency, decimal fractions or real payment rail.

Request IDs match /^txn-[a-z0-9-]+$/; accounts must be distinct, exist as own balance properties, and names must match /^account-[a-z0-9-]+$/. Amount is a canonical positive decimal integer string matching /^[1-9][0-9]*$/, with no maximum imposed by floating-point safe integers. The request object has exactly id/from/to/amount. Reject malformed requests as invalid_request; reject malformed amounts as invalid_amount; reject missing or same accounts as invalid_accounts. These checks occur before any request-history lookup, so malformed retries cannot bypass the contract. Request property insertion order is irrelevant.

For a valid committed ID, identical from/to/amount returns status replayed, the original state object and no mutation or extra audit. A different tuple for that ID returns rejected/request_conflict with the original state object. For a fresh valid ID with insufficient balance return rejected/insufficient_funds and the original state object. All rejected results have exactly status, reason and state; replayed and applied results have exactly status and state. Input request and state must never mutate. A fresh accepted transfer returns a new state object, exact balances conserving total integer units, and one committed requests entry. Append exactly one audit row with sequence (previous audit length+1), request_id, from, to, amount and before/after objects containing from/to balance strings. Preserve all prior request/audit entries and unrelated accounts. Replays of an older committed ID still work after later transfers; rejected IDs are not committed and can be corrected later.

Only src/ledger.mjs is editable. Existing data, documentation and tests are protected. This fixture does not simulate concurrent processes, durable database transactions or real charges. Native tests prove only supplied finite in-memory behavior; absence of earlier unauthorized operations requires separate evidence. No external writes, network, dependencies or real transactions are requested.
