# Search state and view contract
The supplied view adapter renders the controller's notifications; search stays enabled while loading so the user can replace a query. Each search clears earlier visible items/errors and synchronously publishes loading for the current query. Only the most recent search may subsequently publish ready/error; an earlier fulfillment or rejection must neither overwrite the view nor clear its busy state. The transport is allowed to ignore abort and settle out of order.

Call load(query,{signal}) with a fresh AbortController signal for every search. Abort the previous pending request when replacing it. Preserve the latest successful item order and produce error state with message Search failed for a current rejection or synchronous throw. Older failures, including AbortError, must not display an alert. Dispose aborts a pending request, prevents every later notification, and makes later searches no-ops without invoking load. It is idempotent. getState returns a fresh state/items snapshot; load and notify in this exercise provide ordinary string-array data and well-behaved callbacks.

Change only src/search-controller.mjs. Keep the fixed view API, renderer, tests, package and spec. Use ordinary ECMAScript without external dependencies, network, timers or service setup. Deterministic deferred requests replace real services; no runtime timing or empirical reliability is claimed.
