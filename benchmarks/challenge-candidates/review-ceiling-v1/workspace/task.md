# 共有コンソールのリリースレビュー

ReviewOps の移行期間中に、既存のレビュー履歴と旧クライアントを保ったまま、共有コンソールをチームごとに試験導入できるか判断してください。今回の審査範囲は、レビュー結果の引き継ぎ、画面上の作業、性能と運用記録、公開結果の照合です。審査は合成業務資料・実装の読解、オフラインの集計、通常の画面操作で行います。セキュリティ試験は対象外です。

1. 調査前に、依頼と制約を読み、初期判断と調べる順序を `INITIAL.md` に保存してください。
2. `REVIEW.md` にリリース責任者が実行できる判断をまとめてください。配布したコード、業務資料、実行した観測を根拠に、現場への影響、推奨する対応と確認方法を示してください。リリースデスクの集計と導入判断は、別の担当者が同じ記録で再現できるようにしてください。初回の判断には、追加資料を受けた際に参照できる名前を付けてください。
3. 追加の運用資料が引き渡されたら、初回の成果物を保存したまま `REASSESSMENT.md` で判断を更新してください。延期も条件付きの試験導入も、証拠が支える範囲で選べます。

`brief/` は当期の業務要件、`evidence/` は担当部署からの引き継ぎです。追加の観測は `review-probes/` と `review-evidence/` に保存できます。既存ファイルやサービスを変更する作業はありません。Node 24 が利用でき、画面の通常操作はローカルの合成環境だけを使用します。実行できなかった観測はその範囲を記録してください。

100点の内訳は、原因と利用先への影響40、画面操作20、証拠15、優先順位と対策15、検証と再判定10です。
