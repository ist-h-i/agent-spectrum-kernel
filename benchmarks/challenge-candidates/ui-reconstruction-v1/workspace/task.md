# CH08 実績から次の行動を決めるワークスペース

文章仕様から、日本語で使えるローカル完結のWeb UIを新規実装してください。目的は、実績を蓄積し、目標や達成条件へ結び付け、AIの参考案を人間が確認して次の行動を決められることです。目標達成の判断を、取組の完了数やAIの回答だけで確定してはいけません。

読むものは `brief/spec.md`、`brief/data-contract.md`、`brief/scenarios.json`、`brief/rubric.json`、`fixtures/*.json` です。元HTML、画像、CSS、正解UIは提供しません。画面の分け方、導線、コンポーネント、情報の見せ方は設計してください。特定の見た目・文言・フレームワーク自体は加点対象ではありません。

成果物は `app/` に置き、起動方法、設計判断、試験結果、未達を `DELIVERY.md` に保存してください。初回の実装と検証はこのターン内で完了させます。公開入力は変更禁止です。試験結果は実際に確認した範囲だけ記録してください。提出後の第2段階では実装を変更できず、`REASSESSMENT.md` のみ追加できます。第2段階の確認項目は今回渡すシナリオと採点基準の範囲です。

Node 24と現在のブラウザーでlocalhostから使えること。ビルド不要の静的ファイルでも、同梱済みツールを使う実装でも構いません。依存物が必要なら完全に同梱し、外部取得なしで起動できる状態にしてください。認証、サーバー保存、APIキー、実AIは不要です。実行時も開発時も外部ネットワークサービスを使わず、workspace、localhost、許可されたシステムツールだけを使ってください。ホストの別リポジトリ、履歴、非公開採点資料を探してはいけません。データは合成データだけを使います。

`fixtures` の固定JSONを貼り付ける導線と、失敗を再現する試験用操作を用意してください。AIの代わりに固定JSONを使うので、接続やモデル性能に依存しません。試験用操作の名称・場所は自由ですが、DELIVERYに再現手順を記録してください。自動採点用の特定DOM構造や内部関数名は要求しません。

点数は機能70点・UI/UX30点の意味評価です。採点者は実装、実際の操作、提出資料とログを突き合わせます。文章で「できる」と主張するだけでは機能の証拠になりません。実行できない項目は未観測として扱います。生成時間と入出力トークンは別指標で、欠測を0として埋めません。未試行の難度校正や普遍的な性能差は主張しません。
