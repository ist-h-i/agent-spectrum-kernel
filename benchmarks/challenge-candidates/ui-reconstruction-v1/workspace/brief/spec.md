# 行動と判断の仕様 v1

この仕様とデータ契約、公開シナリオ、公開配点だけが要件です。画面の数や元アプリとの外見一致は要件ではありません。

## S1 目標・条件・取組
複数目標を作成、選択、編集する。目標には希望、現状、能力、期限、週時間、除外期間、達成条件がある。条件には検証できる達成基準があり、取組はその条件への行動である。取組に次アクション、成果物、所要時間、未実施／実施済み／保留／置換済みを持つ。置換後も旧取組と後継を確認できる。子取組がすべて実施済みでも条件を自動達成にしない。現在の採用評価がない条件は未判定として見せる。

## S2 目標より先に記録する
目標が0件でも、日付、題名、結果、自己評価、成果物、所要分、支援の有無を記録できる。後から目標・条件・取組へ紐付け、解除・変更できる。記録の編集履歴、論理取消と復元を確認できる。題名・結果の検索、日付範囲、目標、取消の有無で絞る。自己評価は本人の判断と明示し、AI評価や採用評価と区別する。

## S3 計画を相談し、人間が採用する
希望・現状・期限・週時間・除外期間と、変更不可／上限／柔軟の制約を入力し、依頼JSONを含む依頼文をコピーする。計画が未決定、暫定（検証済みの未採用案）、準備済み（採用済み）のどれか分かる。新規目標の手入力保存は準備済みとして扱ってよい。
固定回答を貼り付け、構造、依頼対応、制約を検証してから変更前後を比較する。問題箇所と修正依頼をコピーできる。制約違反・古い依頼・別依頼の回答を適用しない。有効案も確認だけでは反映せず、人間の採用操作で一度だけ反映する。取消は現行計画を変えない。

## S4 評価の根拠・採用・失効
関連条件を指定する評価と、目標全体評価の依頼文を作れる。回答の判定、根拠記録、限界、次の行動を表示する。証拠不足／未達／部分達成／達成を区別する。取組と条件の結果を別々に一部採用・採用取消でき、未採用結果はAI参考のままとする。採用結果も根拠・依頼・対象へ辿れる。失効した結果は履歴に残り、現在の達成数から除外する。再編集で元に戻しても復活させない。失効規則はdata-contractに固定する。

## S5 キャリアの位置づけ
現在／目標達成後／理想を並べて比較できる。責務レベル、5軸、根拠、推定の不確かさと市場条件を示す。現在の事実、AI参考、将来推定を区別し、給与や市場価値の確定事実に変換しない。キャリア参照が古くなったら古い参考情報と表示する。採用による人事評価や給与決定は対象外。

## S6 週報・面談レポート
期間と目標で絞り、週報／面談用を生成する。期間内の有効記録の事実と、生成時点の目標・採用評価・失効状態・次アクションを分ける。取消記録は本文・集計から除外する。自己評価とAI参考の出典を残す。文章コピー、HTML、CSV保存に対応する。HTMLは利用者入力をコードとして実行せず、CSVは先頭が = + - @ の文字列を式として実行させない（単引用符での前置きを許可）。CSVの引用符・改行・カンマを保持する。

## S7 保存と復旧
通常操作をブラウザーへ自動保存し、再読込しても保つ。JSONバックアップは履歴・取消・採用・失効・未消費依頼を含む。復元は構造と参照を検証し、件数と置換の影響を確認後、明示操作で全置換する。確認取消・不正JSON・保存失敗で旧データを壊さない。
通常保存に失敗したら編集内容をメモリーに残し、未保存と警告し、再試行とバックアップを可能にする。採用／採用取消／計画適用／復元は保存成功まで現行の正式状態を変えない。破損した保存値を起動時に上書きせず、原文の退避と検証済みバックアップからの復元を可能にする。別タブの同時編集は単独編集ロックで拒否するか、原子的な更新検出で競合を拒否する。双方成功と表示して片方を消失させてはいけない。競合後はローカル退避と最新状態の再読込へ進める。処理中の二重クリックで同じ記録や採用を増やさない。

## S8 操作と失敗状態
キーボードだけで主要シナリオを完了できる。ラベル、見えるフォーカス、状態の非色依存表現、読めるコントラストを備える。ダイアログを使う場合はフォーカスを閉じ込め、Esc／取消で戻り、起点へ返す。360px幅と1280px幅で主要操作と内容が切れない。保存中、未保存、競合、入力エラー、空、コピー成功／失敗を判断できる。コピー拒否時は選択して手動コピーできる。変更途中の離脱では確認または復帰可能な下書きを用意する。

## 必須範囲と対象外
上のS1〜S8は必須。元HTMLの画面、CSS、文章、実装、バグの再現は対象外。外部AI、アカウント、クラウド同期、添付ファイルの実体アップロード、組織権限、印刷専用レイアウト、全ブラウザー保証、暗黙の市場価格計算、未指定の高度検索は対象外。成果物は説明文字列／URLとして扱い、取得しない。日付はUTCの暦日として扱う。

## 試験環境の制御
試験用操作で「次の保存を失敗」「コピー拒否」「保存値の破損」を再現する。複数タブは同じlocalhost originで開く。時計は試験時に2026-11-13T12:00:00Zへ固定可能にする。固定データの初期化は確認を伴う。エラー注入は試験用と明示し、通常操作と区別する。
