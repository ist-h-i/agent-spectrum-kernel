# CH02 v3 — Durable work during recovery and migration

The reporting service shares a durable job store and an idempotent output sink across restarted workers. Some producers still use the old wire and record formats; maintenance now recovers bounded pages while new work continues. Repair the implementation without changing protected producers or storage primitives so that recovery, cancellation and retry agree with actual durable effects.

Read the contract index in spec/api.md and the fixed producer/store/sink interfaces. Current and legacy clients must continue to work. Observations include exact records/receipts and protected operation counts, not just a final status string. Change src/**, test/added/** and RESULT.md only. Do not modify task/spec/harness/data/package/original tests, install dependencies or access external services. Submit regression tests and a result statement distinguishing actual evidence from missing evidence.
