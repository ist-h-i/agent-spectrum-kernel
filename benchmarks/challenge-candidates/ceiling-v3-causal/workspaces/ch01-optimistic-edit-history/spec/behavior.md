# User-visible editing semantics

Rows are (tenantId,rowId), version>=1 safe integer, name:string, quantity:nonnegative safe integer. An editor's visible state is {confirmed,pending,conflicts,status}; status is idle,pending,confirming,conflict. confirmed reflects the newest known accepted server version; pending contains this client's unresolved field changes. Conflicts are field names (unordered). Values and notification frames are detached copies.

open(rowId,listener) synchronously emits one state and returns an idempotent unsubscribe. Views unsubscribe independently. edit(rowId,patch) returns an opaque operationId and does not send. Nonempty patches contain only valid name/quantity fields; invalid edits throw without effects. Distinct clientId values and distinct sessionKey values cannot generate colliding operations. Default clientId is local. Multiple live instances using the same sessionKey are outside valid producer input, but old disposed instances may receive delayed callbacks.

flush(id) does not create another logical edit. Unknown/cancelled IDs are no-ops. Accepted IDs keep their original request meaning. A later server version must not overwrite pending edits. Different-field remote changes and local edits can both appear after a subsequent flush; overlapping remote updates are visible conflicts, including a change later reverted to its old value. This client's own acceptance is not a remote conflict. Old, duplicated or reordered notifications/replies never reduce the visible confirmed version or retire a different unresolved attempt.

undo(rowId) targets the latest not-yet-undone ordinary edit of this client/tenant, never a compensation. Unsent undo returns null and has no server effect. An operation that may still be accepted remains visibly confirming until its outcome is resolved. Accepted undo affects only the edit's own fields and returns a new compensation ID for the caller to flush. A later accepted update to any target field makes undo a conflict rather than an overwrite. A subsequent update to an unrelated field remains intact. A compensation cannot become the next undo target.

receive(row) consumes an external notification; other tenants and stale versions do not affect the current tenant's view. switchTenant changes the live views to the new tenant while pending edits/undo histories retain their original tenant identity. Disposing or unsubscribing a view never cancels another view's work. Public observations must never expose another tenant's row values. dispose() is idempotent; no later callback or public mutation can affect durable session state or notify its disposed views. Other methods after dispose throw code CLOSED before validating their other arguments.
