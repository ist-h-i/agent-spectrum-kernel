# Session continuity and legacy consumers

createEditor accepts {transport,tenantId,clientId='local',sessionStore?,sessionKey?}. With a sessionStore, sessionKey is a nonempty string. A key belongs to one client lineage; at most one live editor uses it. A replacement editor is constructed after its predecessor is disposed, while server acceptance and replies for old requests can still occur. Different session keys may be live together. SessionStore survives editor replacement, transport and server survive, and only editor process memory is lost.

Every successfully returned mutating API call and every delivered callback before disposal is represented in the durable session. After replacement, unresolved patches, their original logical operation identities, pending undo intent, already accepted undo eligibility and tenant membership are preserved. A restored snapshot agrees with current authoritative server facts and the still-unresolved local work. A lost reply does not permit a duplicate business effect, false cancellation or an operationId with changed accepted content. Old disposed callbacks cannot overwrite replacement state. Internal persistence shape is opaque: tests do not inspect it, and independently implemented editors need not read each other's internal session payloads.

The initial store value may instead be a legacy draft archive. format2 is {format:2,tenantId,drafts:[{operationId,tenantId,rowId,patch,baseVersion,before,order}]}; format1 is {format:1,tenantId,entries:[{id,tenant,row,changes,base,before,order}]}. before contains valid name/quantity; order/base are positive safe integers; IDs are unique/nonempty, rows exist. Unknown format, duplicate IDs, invalid fields/values or missing before are rejected atomically with INVALID_ARCHIVE; no durable write, notification or tenant/history change occurs. Stored internal payloads are values previously produced by the same implementation; adversarial private internal formats are not inputs.

saveDrafts returns a detached format2 archive of unresolved unsent operations in original order, including unsent compensation as a restorable ordinary edit. Accepted/cancelled history and subscriptions are not draft entries. If any transmission or undo outcome remains unresolved it throws BUSY without effects. restoreDrafts is atomic, requires empty local history (NOT_EMPTY wins over archive errors), preserves identity/order/before/base, sends nothing and keeps current server facts. Restored draft IDs cannot collide with future edits. A replacement's session persistence is broader than this draft-only public interchange format.

createLegacyAdapter supports setCell(label->name,stock->quantity), send({op}), undo(rowId) returning {op} or null, and view(rowId)->{rowId,label,stock,dirty,busy,conflict}. Unknown columns throw before changes. Values reflect current confirmed+pending values; dirty means nonempty pending, busy means confirming, and conflicts map to label/stock. Legacy and current callers share one editor state. No procedure or internal ownership layout is required.
