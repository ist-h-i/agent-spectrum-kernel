# Events and visible transitions

S1 `src/pipeline.mjs:createPipeline({windowSize,allowedLateness,sink,checkpoint?})` returns ingest,ingestBatch,ingestEnvelope,advanceWatermark,exportCheckpoint,stats. windowSize is a positive safe integer and allowedLateness a nonnegative safe integer. `src/processor.mjs:createProcessor` preserves ingest/advanceWatermark/stats. `src/legacy.mjs:createLegacyConsumer(pipeline)` exposes push(event) with the same acceptance/effects as ingest of that legacy event, and watermark(tenant,value) with the same acceptance/effects as advanceWatermark. Calls are synchronous. Fixed sink.finalize/reject are synchronous and do not throw on declared valid input; no crash between individual in-process statements is required. Re-instantiation with an exported checkpoint is a supported process boundary.

S2 Modern events are `{tenantId,eventId,revision,eventTime,amountMinor,deleted}`: nonempty string IDs, nonnegative safe integer revision/time, canonical signed integer decimal amountMinor (`0`, or optional minus followed by nonzero digit/digits), boolean deleted. Legacy events are `{tenant,id,rev,at,cents,remove}` with identical meanings. Unknown properties are ignored. Inputs are caller-owned and must not be mutated or retained by reference. `eventTime` is immutable for an active `(tenantId,eventId)`. The greater revision wins; an older revision is an accepted no-op; equal revision/equal amount and deleted is an accepted no-op; equal revision/different content is `revision_conflict`. A deletion marker retains its revision until closure. Tenant and ID are jointly significant.

S3 Window start is floor(eventTime/windowSize)*windowSize, end=start+windowSize. Ingest rejects if end+allowedLateness<=that tenant's watermark. Before any watermark the tenant has no closed windows. An ID no longer retained after closure is rejected by its eventTime/window. Output totals are exact decimal sums of the latest nondeleted revisions. A window that has accepted only deletion markers still closes with zero; a never-observed window has no output. No early or repeated output.

S4 `ingest(event)` returns `{accepted:true}` or `{accepted:false,reason}` and records one sink rejection for an invalid/conflicting/closed event. Error priority: invalid_event, event_time_conflict, closed_window, revision_conflict. An older revision otherwise has no effect. Rejections do not alter the accepted state. `advanceWatermark(tenant,value)` accepts nonempty tenant and nonnegative safe integer value >= previous watermark, returns `{accepted:true}`; otherwise `{accepted:false,reason:'invalid_watermark'}` without sink/state effects. Accepted calls emit newly closed windows ordered by start, leave other tenants unchanged and reject future late events. Equal watermark is accepted and emits nothing new.

S5 `ingestBatch(events)` accepts an array length<=256. Invalid array/length returns `{accepted:false,index:null,reason:'invalid_batch'}`. Otherwise the return is `{accepted:true,count}` or `{accepted:false,index,reason}` at the first failing element under S4. On element failure no element is accepted, and exactly that one rejection is recorded. Caller input is unchanged. Order within the batch is meaningful.

S6 `ingestEnvelope` and persistent format are defined in storage.md. It has different rejection-side-effect rules from ingestBatch. All state, accepted outputs, sink rejections and exported values must satisfy the stated contract after each public call, including calls alternating legacy, individual, batch and envelope entry points. Internal representation and scan order outside stated output ordering are not observed.
