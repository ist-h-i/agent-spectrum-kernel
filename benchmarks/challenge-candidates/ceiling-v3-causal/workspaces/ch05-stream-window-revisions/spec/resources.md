# Fixed resource contract

R1 Measure completed finite work, not a walltime score alone. The public recipe data/load.json fixes tenant counts, event IDs, revisions, rounds, watermark schedule, repetitions and runtime. A result must contain every expected completed interval and no late acceptance/duplicate effect. Provider-side sink counts are authoritative; submitted stats are diagnostic only.

R2 Observable checkpoint space is bounded by currently active event IDs E, active windows W, known watermarked tenants T and known producer pairs P. Checkpoints retain exactly E current events, T finite watermarks and P latest delivery bodies. Necessary producer bodies can grow with P and their latest batch lengths; they are not classified as disposable closed-event history. No O(total closed event revisions) rows may remain in events. More active IDs/tenants/producers legitimately require more state. JSON byte length of a fixed encoding is an additional space observation, not an assumed bound independent of live cardinality.

R3 The fixed steady profile has4 tenants,128 distinct IDs per tenant/round,3 revisions/ID,200 rounds. Every round advances each watermark past all that round's windows. The active_growth profile has4 tenants and8192 IDs per tenant,one revision (revision0), and no closing watermark before final observation. Each profile uses a fresh measured processor and one ordinary32-event warmup in a separate discarded processor. Each runs3 times with explicit GC before baseline, at each watermark or4096 records, and after the last input. Runtime is Node24.21.0 Linuxarm64 CPU1/512MiB/PID64; image/setup/timeout failure is unknown, not a low solution score.

R4 Steady sampled heap growth limit32MiB and RSS growth192MiB; active_growth limits64MiB/256MiB. These are proposed fixed supplementary ceilings pending both correct designs' runtime qualification. They are not calibrated achievements and cannot be changed after candidate scores are observed. Walltime is recorded, and the each separate profile scenario has a90s worker limit within a120s container termination limit; no standalone10s scoring threshold applies. Logical counts and exact output totals must pass independently of memory/time. `stats()` is not used as proof of retained size or work.

R5 `harness/logical-profile.mjs:runLogicalProfile({mode})` accepts closed/live/producers. It returns declared recipe cardinalities, protected call counts and counts of accepted:true responses, checkpoint-space samples and sink counts. closed:96 rounds,4tenants,8IDs,3revisions and round closure; live:1round,4tenants,192IDs,3revisions without closure; producers:96rounds,4tenants,16producers each with one event/delivery and round closure. Checkpoint shape follows P3. accepted is a report of submitted API responses, not an independent completion proof. Exact sink effects and checkpoint contents provide independent consistency observations. These finite ordinary load profiles contain no rejected input or hidden expected-value oracle.
