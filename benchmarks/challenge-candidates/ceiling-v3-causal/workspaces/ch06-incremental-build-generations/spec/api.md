# Requests and visible results

B1 `src/workspace.mjs:createWorkspaceBuilder({compiler,publisher,concurrency})` exposes build(snapshot),buildLegacy(legacy),cancel(projectId,generation). concurrency is positive integer. Modern snapshot is `{projectId,generation,compilerVersion,config,files,targets?}`; projectId is nonempty string (omitted means default), generation positive safe integer, config JSON object and compilerVersion string. files maps normalized relative POSIX paths to `{text,imports?,discover?,globs?,fail?}`. Omitted arrays mean empty, omitted fail means false. All inputs are caller-owned JSON; later caller mutation after build returns its promise cannot affect that request. Config object-key order recursively has no meaning; config array order does.

B2 targets is an optional array of file names; omitted means all file names. Duplicates and ordering have no meaning. An empty target set is valid. A target not in files or a non-array/non-string target encoding returns status rejected/reason invalid_targets without provider/publication/cache effects. Only selected targets appear in results. Source dependencies can be unselected targets but their artifacts are necessary when reachable from selected targets. Files outside that reachable dependency graph cannot cause failure, compiler work or public results for this request. Reachability includes declared imports, glob matches and dependencies returned by the compiler. A source with no path from a selected target is not made relevant solely because it is present in files.

B3 Legacy wire is `{project,revision,compiler,settings,sources:[{path,body,requires?,discover?,globs?,fail?}],entries?}`. settings is config object or JSON object string, requires maps to imports, entries maps to targets. Omitted entries means all sources. Duplicate source paths return rejected/duplicate_path without provider/publication/cache effects. Default-project `src/builder.mjs:createBuildSystem(options).build(oldSnapshot)` retains the old `{generation,results}` result, equivalent to modern default with status/project fields omitted. Unknown auxiliary producer metadata has no compilation meaning. Producer inputs otherwise satisfy the declared shape/ranges.

B4 A project accepts a strictly greater generation or an identical normalized snapshot at its current generation. Input identity includes project, generation, compilerVersion, canonical config, all file contents/metadata and the target set. Older generation returns rejected/stale_generation; changed current-generation identity returns rejected/generation_conflict. Priority is malformed target encoding, then generation comparison. Neither rejection supersedes another request, changes visible state, adds compiler work or publishes. A valid build returns `{projectId,generation,status:'completed',results}` even if selected targets failed. Missing dependencies fail affected targets; unaffected selected targets can succeed. Current input may be rerun as a distinct request.

B5 Cancellation cannot stop provider calls already started. cancel(project,generation) returns true iff it marks any still-running attempt at that generation. Queued calls for marked attempts never start afterwards. Those requests settle after their started calls settle, return status cancelled/results:{}, publish nothing and cannot change artifacts reused by later requests. Other projects and later identical reruns remain live. Completed requests are no longer cancellable. Inputs and visible result ownership are detached.

B6 Exactly one coherent result is published for each completed request that is still the latest noncancelled accepted request of its project. Canceled/superseded completions produce no publication, including while a later request is pending. Other projects' generation numbers do not supersede this project. Rerunning current input may publish once. A prior visible result may remain and identifies its project/generation. No partial publication, cross-project artifacts or process-global cross-instance mutable state.
