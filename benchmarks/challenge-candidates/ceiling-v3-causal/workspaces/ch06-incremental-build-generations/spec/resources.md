# Work and progress bounds

Q1 One builder's active compiler calls across projects/overlapping requests never exceed concurrency. Every ready independent selected target must progress under fair finite provider completion, including after cancellation of other work. All issued requests must settle after the protected scheduler has fairly completed the work needed for those requests. No fixed ordering between independent projects is required.

Q2 For a completed current noncancelled warm request, an identical rerun makes zero additional compiler calls. A local change can affect its own reachable importers and glob/discovery relationships; selected targets whose source/compiler/config/dependency artifacts are unchanged require zero additional compiler calls. Target-set changes may reuse equivalent artifacts. A failed output is never reused as success. Canceled/superseded work cannot alter a later request's reuse or visible results. Dependence on removed glob members or obsolete discovered edges must not persist. Only artifacts relevant to the current selected targets need remain available; new-generation warm reuse is required only as stated here, not for arbitrary evicted old target sets.

Q3 Producer limits:8 projects,32 files/project,each source text<=4096bytes,at most8 imports/discoveries/globs per file,64 accepted requests/project,concurrency1..4. Inputs and dependency graphs are finite. For a new current request with N reachable source files and complete dependency sets supplied by the fixed compiler, successful acyclic cold work uses at most2N compiler calls; failures cannot create unbounded calls. Empty targets issue0 calls. Observations come from protected compiler records rather than submitted counters. Logical work is primary; walltime is only a recorded diagnostic and the environment's120s termination bound. No disk cache/network compiler/background watch/retry service/cross-process sharing is required.
