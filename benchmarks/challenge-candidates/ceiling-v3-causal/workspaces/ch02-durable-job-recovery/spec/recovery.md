# Recovery pages and repeatable measurement

recover() remains the whole-store compatibility operation. recoverPage(cursor=null,limit=16) returns {cursor,done,visited,jobs}. jobs describes precisely the visited records after that page's recovery; order matches the protected page. cursor is null at completion. A new null cursor starts a new finite pass. limit is an integer1..32; invalid limit/cursor is INVALID_CURSOR with no store/sink mutation. Cursor error wins over record errors outside the requested page.

DurableStore.page captures an insertion ceiling on its first call and returns up to limit entries after its continuation position. Existing keys keep insertion identity when their values change. Insertions after the captured ceiling are absent from that pass, and included in a later null-cursor pass. Returned record values are current detached values. A continuation is replayable after a lost response; no cursor-local mutable queue state is necessary. Cursor contents are opaque to clients. A finite completed pass visits each key at its ceiling once; replaying a page can revisit it but cannot duplicate business effects.

Valid format1 records in a page become equivalent current records. Invalid record anywhere in that page means the complete page leaves store/sink unchanged. Later pages need not be validated by an earlier page. On success, all visited records agree with the output/cancellation/lease facts in jobs.md. If PROCESS_CRASH occurs before-page,after-page-read,after-page-commit,before-evidence or after-evidence, callers may retry the same cursor or begin a fresh pass using another queue instance. Previously committed durable state may be visible after an interruption; honest final states and eventual fair progress remain required. The store transaction covers only store values; sink effects cannot be rolled back.

Protected counters are read-only observation(): reads,casCalls,scanVisits,pageCalls,pageVisits,records. They cannot be reset by a candidate. A noninterrupted recoverPage visits at most limit records through page, makes zero full-scan visits, at most24*limit+8 read calls and12*limit+4 CAS calls. INVALID_CURSOR can increase pageCalls but has no value effects. Transaction rollback does not roll back observation counters. These are logical work bounds for the provided primitives, not candidate self-report or noisy walltime thresholds.

Fixed validation load: <=128 records across8tenants,<=64KiB each; <=256 lease acquisitions and <=32 recovery-page retries; clocks/tokens remain safe integers. Records are not deleted from the store and no concurrent thread runs JS; finite hook interleavings and later insertions are supported. Finishing any full pass and fair retries after the last interruption must not starve a valid unrelated job. Every source implementation must satisfy the bounds; no exact scan/claim order or internal token-allocation algorithm is prescribed.
