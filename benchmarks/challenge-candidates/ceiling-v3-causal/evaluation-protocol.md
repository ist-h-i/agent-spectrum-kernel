# Evaluation and evidence contract

The public quality dimensions are required behavior30, compatibility/coherence30, failure/liveness25, added-test effectiveness10 and scope/maintainability5. Independent observable obligations yield partial credit; duplicate names for the same obligation must not create duplicate penalties. Algorithms, source-file count, opaque identifier encodings and schedules not fixed by a caller contract are not scored.

Severe safety effects are separately observed. An unsafe artificial control is not a candidate safety violation. Unknown evidence is null; infrastructure/setup/import faults never count as successful semantic fault detection. Legitimate candidate load/timeout failures are distinguished from evaluator and normal-control failures.

Added tests use test/added/scenarios/*.test.mjs with the existing declared JSON scenario protocol. The identical tests must pass both structurally different normal designs before assertion failures on meaningful semantic faults earn points. Always-failing tests and source/setup errors do not earn detection credit. Independent assertion provenance confirms that the observed failure concerns the intended public behavior. A test workspace never receives private solution sources; the solution service receives only bounded public-API JSON operations, not submitted test JavaScript.

Public capabilities specify the complete operation vocabulary and resource-profile tags. Each normal program watchdog is15s; at most6 normal programs share a120s service container. Resource programs use the declared90s profile and one container each. These are protective deadlines, not the task's performance score by themselves. Task-specific fixed loads, operation/space bounds and cardinality assumptions define quantitative behavior. Counts must come from protected observations or a declared independently measured process, not unverified candidate self-reports. Environment-sensitive measurements are supplementary and need a fixed runtime/warmup/workload/GC policy with normal controls.

Before any model measurement, freeze the task inputs, scorer, correct controls, semantic faults, public capabilities, resources and weights; independently verify contract sufficiency, excess solution hints, preservation of seed defects and measurement/scoring coverage. At least two valid designs and corresponding semantic faults require actual execution evidence. Static review does not supply it. Holdout and post-freeze confirmation are separated from calibration; a Full ASK-only calibration would have selection bias. No30–70 score or reduction is promised or used as an adoption gate.

This source package includes no authorization for Docker, model/authentication use or additional execution slots. Existing version results and consumed budgets remain unchanged.
