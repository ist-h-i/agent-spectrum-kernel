# CH01 v2 — 編集端末の状態と旧draftの移行

在庫端末は編集、履歴、通知cacheを別々に増設してきました。旧端末はlabel/stockのwire APIとv1 draft保存形式を使用し、新端末はname/quantity APIを使用します。複数端末が同じtenantを編集し、応答と通知の順序は一致しません。利用者が見た未確定入力とundo対象が消えたり、旧draftを開くと別tenantの値が表示される問題を、互換性を維持して解消してください。

主要familyは (A) 編集・履歴・購読の一貫性と複数利用者、(B) 旧wire/保存形式の互換と原子的draft復元、(C) 応答不明・再送・補償undo・tenant切替の競合です。`spec/api.md` のv1互換契約および追加条項がすべて公開要件です。内部構成の統合や別設計を許し、ファイル数や設計パターンは採点しません。

`src/editor.mjs` のcreateEditorと`src/legacy.mjs` のcreateLegacyAdapter、`src/session.mjs` のdraft codec、`src/history.mjs` の旧history責任は協調して使われています。harness/legacy-clients.mjs、views.mjsは変更できない実利用者です。互換APIだけ直して新APIを壊す、あるいはその逆では解決しません。

変更可能: src/**、test/added/**、RESULT.md のみ。計測メモやscratchは/tmpまたはtest/added/artifacts/**へ。task/spec/harness/data/元test/packageは保護対象です。外部依存・download不要、Node24.21.0/Linuxarm64、CPU1/512MiB/PID64、ネットワーク/host mountなし。追加採点testのscenario形式はspec/scenario-tests.mdに従ってください。通常testが通ることは全契約の証明ではありません。

seedに既知の正解・不良一覧やprivate採点器は含みません。目標点やテスト件数で採点を決めません。
