# CH02 v2 — 旧ジョブ形式を残した永続処理の復旧

帳票サービスは旧wire APIとv1の保存jobを運用したままlease workerへ移行中です。受付、状態表示、回復処理、取消が別々に実装され、旧jobの状態理由と新workerの出力確定が食い違います。storeとsinkを共有する別queue、同じworker名の再取得、出力後crashを含め、再起動しても同じ依頼の出力と取消の事実を保ってください。

主要familyは (A) 旧wire/保存形式と新APIの互換・原子的移行、(B) lease fencingと取消/失敗理由、(C) sinkとstoreの照合・crash回復・無関係jobの進行です。必要な原子性は公開protected store.transaction/CASとsink.putIfAbsent/closeIfAbsentが担います。storeとsinkを跨ぐ分散transactionは要求しません。実装は公開primitiveと結果照合で不明状態を解消します。

`src/queue.mjs`, jobs.mjs, records.mjs, legacy.mjs が増設時の責任分裂を持ちます。固定client/legacy-clientsは新旧両方を利用します。spec/api.mdの全条項を満たし、内部アルゴリズムは自由です。

変更可能: src/**、test/added/**、RESULT.md のみ。scratch/計測は/tmpまたはtest/added/artifacts/**へ。その他は保護対象。Node24.21.0/Linuxarm64、CPU1/512MiB/PID64、ネットワーク/host mountなし、外部依存不要。scenario追加testはspec/scenario-tests.mdに従います。テスト件数・恣意的な上限で点数は決まりません。
