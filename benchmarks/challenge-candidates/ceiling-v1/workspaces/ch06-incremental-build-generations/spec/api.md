# Incremental build API v1

`src/builder.mjs` exports `createBuildSystem({compiler,publisher,concurrency})` with positive integer concurrency. It returns `build(snapshot): Promise<{generation,results}>`. Multiple build calls can overlap. Calls use strictly increasing positive safe integer generation, except re-running the same snapshot/generation is allowed. Snapshot is immutable caller-owned data; build must capture it before asynchronous work and must not mutate it.

Snapshot: `{generation,compilerVersion,config,files}`. `files` maps normalized nonempty relative POSIX paths (no `.`/`..`) to `{text,imports?,discover?,globs?,fail?}`. Text is a string; imports/discover are exact file paths; globs are strings containing at most one `*` which matches a filename segment, never `/`. Absent arrays mean empty. Config is a plain JSON object with keys inserted consistently by producer; compilerVersion is a string. `fail:true` represents a compile error. Every file is a build target.

Protected compiler:

- `compiler.inspect(snapshot,path)` returns `{imports,globMatches}`, sorted distinct lists. Glob lists are re-evaluated against that snapshot, including newly added/deleted paths. Compile-time discovered dependencies are reported by compile, not inspect.
- `await compiler.compile({snapshot,path,dependencies})` accepts `dependencies` as an object mapping dependency path to its string artifact. It resolves to `{status:'dependencies',paths}` if required artifacts are absent, where paths includes the complete dependency set discovered so far; `{status:'ok',output,dependencies}` on success; or `{status:'failed',reason,path}`. Known compile-time discovered dependencies must be reconciled before successful compilation. The compiler's string outputs are deterministic in path, text, compiler version, full config and sorted required dependency path/output pairs. It rejects missing sources and missing dependencies. Its observation API records every call and concurrent active calls.
- Manual mode only resolves a request when `complete(id)` is called. `pending()` exposes IDs, generations and paths. Auto mode resolves immediately by Promise. No execution time or output depends on host clock or network. `harness/scheduler.mjs` drives finite deterministic completions; a caller may choose any pending ID to reproduce completion reversal.

Results have exactly the snapshot's file keys. Each result is `{status:'ok',output}` or `{status:'failed',reason,...}`. Missing-source dependency and compiler failures must mark the affected target and its transitive importers as failed. A cycle result uses `reason:'cycle'` with `cycle:[paths...]` identifying a closed dependency walk (first path repeated last); affected dependents may use `reason:'dependency_failed'`. Independent targets must still finish. Failure reason for direct compiler failures is the compiler's reason; a dependency failure uses `dependency_failed` and identifies the dependency in `dependency`.

Publisher: `publisher.publish({generation,results})` synchronously records a deep copy. Publish exactly one final coherent result for the most recently requested generation; never publish an older completion after a newer request, including while the newer build is pending. A superseded build may finish its returned Promise with its own result, but must not alter the visible latest state. The prior successful result may remain visible until new publication; its generation identifies it as old. No partial success publication is supported. `harness/consumer.mjs` displays both generation and per-target status.

Cache reuse is allowed only for matching path, source, compiler version, config and dependency set/outputs; generation alone does not invalidate equivalent content. A successful repeated build with identical inputs must make zero additional compiler calls. After a local text edit, targets with unchanged inputs and dependency artifacts must reuse cache; unaffected independent targets make zero additional calls. Cold discovery can require an extra call, so efficiency is compared after one completed warm build. Never reuse a failed output as success. The total active compiler calls across overlapping generations must not exceed concurrency. Independent ready targets must progress once pending calls are fairly completed.

Run `npm test` using Node 24.19.0, no dependency installation. Mutable submission paths are src/, test/added/, RESULT.md. Do not change fixed compiler, scheduler, clients, data, spec, package or original tests. `watch.mjs` materializes the finite artificial changes from data/watch-events.json.
