# Fixed measurement recipe ch05-load-v1

Use Node **24.19.0**, one process, no competing benchmark, `node --expose-gc harness/measure.mjs`. Retain full JSON lines, OS/CPU/RAM identity and resource limits. Inputs come lazily from generator.mjs, not a retained array. No network or external dependency is needed. The sink uses a rolling digest and counts; it does not collect rows. The recipe is data/load.json and must not change after reference calibration or during model comparison.

Steady load: 4 tenants, 200 rounds, 128 new IDs/tenant/round, three revisions/ID (revision 2 deletes every seventh ID), width 1000 ms and L=200 ms. Times are round*1000+id. For each tenant/round, ingest revisions in increasing order, then advance only that tenant to (round+1)*1000+200. Thus at most 128 active IDs per currently loaded tenant/window, with bounded live cardinality and increasing closed history. This measures disposal of closed history separately from increasing live state.

Active-growth load: 4 tenants, 8192 IDs/tenant, no watermark, one revision each, eventTime=id*1000. This deliberately grows both active IDs and windows to 32768. Its memory is reported as necessary live-state cost rather than a closed-history leak. The retained tenant count is four in both profiles; a separate correctness scenario may add tenants and must account for one watermark per observed tenant.

The process records heapUsed/RSS after explicit GC at each steady watermark or each 4096 growth inputs, plus baseline/final, sampled peaks, elapsed wall time including GC, exact input count, digest and environment. Each profile is run three times in the same process with fresh processor/sink; reference calibration must use this same order and runner. Sampled peaks are not claimed as the OS absolute peak. Runtime and GC overhead are included consistently.

**Thresholds are pending** (`null` in load.json). Correct reference and independent alternate reference must first produce matching outputs and complete this recipe on the selected CPU/RAM/container limits. Freeze environment, upper time/heap/RSS bounds with headroom and hash of recipe before model runs. No performance pass or measurement readiness is claimed before that calibration. Active-growth profile is reported separately and must never be required to fit a constant bound for increasing live cardinality. Do not adjust bounds after viewing model results.
