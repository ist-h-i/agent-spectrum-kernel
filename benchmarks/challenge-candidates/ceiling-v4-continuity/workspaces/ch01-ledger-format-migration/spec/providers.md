# Provider ownership and finite interruption model

The provider exposes copies, never live references. `inspect(tenant)` returns `{head,version,cursor,activated}`. Head is the count of accepted transactions; the first sequence is 1. `request(tenant,requestId)` returns the first matching raw transaction or null. `scan(tenant,after,limit,through=MAX_SAFE_INTEGER)` returns raw transactions with after < seq <= through, at most limit, in sequence order. `row(tenant,id)` returns `{cursor,row}` at the same snapshot point; row may be null. `snapshot(tenant)` returns `{version,cursor,rows,activated}`.

`append(tenant,expectedHead,{requestId,changes})` atomically compares head, and on equality appends one copied raw transaction and returns it. On inequality it returns null without effects. Append does not compare request IDs, convert values, maintain the snapshot, or validate application arguments. Its inputs must satisfy the published raw record schema. It is the caller's responsibility to establish request identity. No cross-tenant primitive exists.

`commit(tenant,expectedVersion,{cursor,rows,activated})` atomically compares snapshot version. On equality it replaces the snapshot tuple and increments version, otherwise returns false without effects. Cursor must be a safe integer between current cursor and current head. This primitive does not establish the correctness of rows or that the scan covered cursor. `activate(tenant,version,head)` atomically compares both current version/head and cursor=head; on success sets activated and increments version. It returns false without effects on any mismatch. There is no multi-call transaction across append and commit.

`once(point,callback)` installs one synchronous callback, consumed before it is invoked; any throw propagates. Points are `scan:returned` (copied result fixed, immediately before returning), `write:beforeAppend`, `write:afterAppend`, `migration:beforeCommit`, `activation:beforeCommit`. Ledger calls the latter four via provider `boundary(point)` at the named public boundary; additional points are forbidden and arbitrary candidate callbacks need not be supported. Only these finite interleavings are required. Hooks may invoke another Ledger or the legacy client and then throw; the primitive comparisons still apply at the stated points. A scan result remains the prefix copied before its callback.

Protected counters: `eventsRead` counts raw transactions copied by scan, successful request lookup and export, `rowReads` counts row calls, `snapshotRows` counts materialized rows copied by snapshot and export, `appends` successful appends, `commits` successful snapshot commits. An export copies every retained transaction and snapshot row across all tenants, so those full counts are added once per export. Its returned image shape and durable semantics are unchanged. A request lookup returning one existing transaction adds one eventsRead unit; an absent lookup adds zero. These units measure materialized records, not the provider’s internal indexing or search CPU cost. `stats()` returns cumulative copies and does not reset. External consumer inspection is excluded by before/after differences around the measured Ledger call.
