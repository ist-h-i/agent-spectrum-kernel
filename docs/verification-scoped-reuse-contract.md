# Verification Scoped Reuse and Coverage Contract

This contract extends the Slice 1 verification-evidence contract without changing the meaning or bytes of the existing exact-reuse, transfer, or evidence artifacts.

The machine-readable contract is `schemas/verification-scoped-reuse.schema.json`. The implementation is `scripts/verification-scoped-reuse.mjs`.

## Scope

This revision adds the deterministic Slice 2 and Slice 3 control-plane pieces for Issue #274:

- source-controlled dependency manifests;
- actual Git inventory comparison across revisions;
- `reuse_scoped`, `rerun_required`, `independent_judgment_required`, and `blocked_uncovered` planning;
- bounded delta-review request construction;
- fail-closed current-target coverage.

It does not run an LLM review, skip GitHub CI automatically, refresh PR/CI/approval state, or claim measured token, elapsed-time, or quality improvement. The Slice 1 exact-reuse API remains the authority for same-target exact reuse.

## Source-controlled dependency authority

Scoped reuse does not accept a caller-supplied list of supposedly unchanged paths. A required gate points to a dependency manifest that already exists at the source evidence revision. The source evidence must include that manifest itself as a consumed `manifest` input with the exact raw-byte digest.

A complete dependency manifest binds:

- gate ID and gate-contract digest;
- file, directory, or glob selectors and the evidence kind assigned to every selected path;
- the exact source-revision selected-input inventory digest;
- command and runner identity;
- the supported runtime observation mode;
- `unknown_dependencies_require_rerun: true`.

The manifest must not select its own path. This avoids a self-referential content digest while still binding the manifest through the signed source evidence.

`dependency_completeness: incomplete`, an unsupported runtime observation, a missing or changed manifest, a manifest whose base inventory no longer matches Git, or an input type the planner cannot verify all fail closed to rerun or uncovered state.

## Actual Git inventory

The planner resolves full commit SHAs and compares Git tree inventories, not workspace timestamps or a caller-authored changed-file list.

For every selected input it records:

- repository-relative path;
- Git mode and object type;
- Git object ID;
- raw content SHA-256 for blobs;
- evidence kind declared by the manifest.

This detects content changes, additions, deletions, rename/copy effects, and mode/type changes. Directory and glob selectors are evaluated independently at the source and target revisions, so a newly added matching file invalidates the gate even if it was absent from the original evidence.

The Git `--name-status -M -C` diff is retained as a bounded review reference. It is not the authority for deterministic reuse; selected inventory equality is.

## Source evidence binding

A scoped pass requires an existing Slice 1 verification-evidence object whose producer signature and content-addressed identity verify successfully. The object must bind exactly to:

- the repository derived from the canonical GitHub `origin`;
- the source revision and its Git-tree digest;
- the gate and manifest gate-contract digest;
- the manifest command and runner;
- every selected source input plus the dependency manifest, with no hidden or omitted consumed input;
- all required obligation refs;
- an accepted producer pair and evidence level;
- a successful terminal result.

The current implementation observes Node directly from the running process. The source evidence must use the standardized `node_process_v1` Node toolchain and `{platform, architecture}` environment identities generated by `currentRuntimeIdentity()`. A changed or unobservable runtime falls back to rerun.

An old exact-only evidence object that was not produced with these scoped bindings is still valid Slice 1 evidence, but it is not silently promoted to scoped reuse.

## Dispositions

For each current required gate, the scoped planner emits one disposition with the evidence, manifest, source/target inventory, obligations, and reason used:

| Disposition | Meaning |
|---|---|
| `reuse_scoped` | The target revision differs, while the complete declared dependency inventory, manifest, execution contract, runtime identity, producer authority, and obligation coverage remain valid. |
| `rerun_required` | A required dependency, contract, runtime, authority, obligation, or binding changed or cannot be validated, and execution is available. |
| `independent_judgment_required` | Deterministic execution evidence remains reusable, but current independent judgment is still required. |
| `blocked_uncovered` | The same failure exists and current execution is unavailable. |

`reuse_exact` remains part of the shared state vocabulary, but same-target exact planning continues through the unchanged Slice 1 exact planner.

The plan also records full-rerun gate count, reused execution count, required rerun count, and saved execution-gate count. These are deterministic gate counts only. They are not token, latency, cost, or quality measurements.

## Target requirements boundary

Current gate inventory is read from the fixed source-controlled path:

```text
.ask/verification-scoped-requirements.json
```

The planner reads that artifact from the exact target commit. A caller cannot submit a reduced in-memory obligation set to the planner after observing the result. The requirements artifact binds source revision, manifest path, source evidence ID, required obligations, accepted producer/evidence authority, execution availability, optional delta-review surface, and any current external-state obligations.

Changing this artifact creates a new target revision and a new requirements identity. It does not rewrite the historical source evidence.

## Delta review request

The delta-review builder does not call a model. It produces a bounded reference artifact containing only:

- source and target revisions;
- the plan and Git-diff digests;
- affected repository-relative paths selected by declared review surfaces;
- obligation refs;
- prior review/finding refs;
- reusable verification-evidence refs.

It does not store raw diffs, prompts, transcripts, raw command output, secrets, or private evaluator content. A truncated Git diff or more than 256 affected review paths yields `blocked_unbounded` instead of silently omitting context.

A prior review is only a baseline reference. When a declared semantic surface changed, the request reports `current_judgment_required`; the historical review is not projected as a current independent decision.

## Current-target coverage

`buildCurrentCoverage()` recomputes the scoped plan from the target Git revision, evidence store, and target requirements. Coverage is `covered` only when every deterministic gate is `reuse_exact` or `reuse_scoped`, no current delta judgment is outstanding, and no required current external-state observation remains.

Current PR HEAD, required CI, approvals, mergeability, release state, authorization, and other external facts are deliberately not accepted from historical JSON. If the target requirements declare one of these obligations, coverage reports `current_observation_required`. The schema does not accept a caller-provided `fresh: true` escape hatch.

This coverage artifact is not merge or release approval. It only states whether this contract's declared current-target obligations are covered.

## CLI

The planner uses explicit repository, evidence store, and full target commit inputs:

```bash
node scripts/verification-scoped-reuse.mjs plan \
  --repository /path/to/repository \
  --store /path/to/evidence-store \
  --target <full-target-commit>

node scripts/verification-scoped-reuse.mjs delta-review \
  --repository /path/to/repository \
  --store /path/to/evidence-store \
  --target <full-target-commit>

node scripts/verification-scoped-reuse.mjs coverage \
  --repository /path/to/repository \
  --store /path/to/evidence-store \
  --target <full-target-commit>
```

An optional `--output` uses the existing atomic no-replace JSON publication helper.

## Integration boundary

This revision is library/CLI first. It does not force the planner into CI or review routing. The repository workflow runs its deterministic contract test so the implementation itself remains covered.

Issue #275 checkpoint/snapshot state is not consumed. The existing shared content-addressed store is reused only for verification evidence; no second CAS, C4 dependency graph, or review approval engine is introduced.
