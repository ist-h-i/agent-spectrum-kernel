# ADR-0016: Evaluate exact environments while retaining individual Asset authority

- Status: Proposed
- Date: 2026-11-05
- Upstream: ADR-0003, ADR-0004, ADR-0005, ADR-0014
- Supersedes: None

An instruction environment is a CAS projection of independently registered
Skills/Prompts plus explicitly selected supporting files. It is not a new Asset
type, Registry, Portfolio, scoring policy, current pointer or adoption authority.
An authoring export may have no Portfolio selection; an evaluation must bind the
complete selected instruction set and its exact existing Evolution roles.

The additive `instruction_environment_v1_exact` Evolution projection binds both
environment object digests before outcomes. Each adapter has a separate
experiment. Supporting bytes and runtime identity cannot drift within a declared
one-factor change. Existing recommendation, approval and rollback authority still
apply. The existing generic materializer/runner execute the exact full-profile
environment; the Codex primary and its scoring/admission inputs are unchanged.

Mechanical invocation evidence, tool results, command expansion, self-report and
quality outcomes remain separate. Missing events are unobserved. A local import
never turns exporter configuration on or authenticates the supplied log.

Fresh/manual targets use the existing installer lifecycle and lock/state slot.
The continuation also explicitly generalizes the paired lease to exact
instruction paths in current full Codex/Claude installations: independently pin
the original normal owner, preserve protected files/settings/other owners,
advertise the actual selected capabilities in the delegated state, and require
separate rollback authority before exact owner return. Immutable operation
history prevents adoption-receipt replay. Kernel/adapter entry points refuse
mutation while delegated or partial. ADR-0014's five-Prompt lease stays separate.
Unreviewed profiles/source migrations and automatic partial repair remain refused.

Root Skill membership is represented by a real environment revision: compile
the actual runtime instruction files into the existing rendered Prompt bundle,
with the individual Assets as exact dependencies and a verified CAS renderer
input inventory. Compare environment bundle revisions; never invent a Skill
parent or promote component lifecycle/effectiveness from compilation. Saved
grades re-enter the existing original verifiers and descriptive evidence mapper;
the adapter grants no evaluation trust and invents no unobserved dimensions.

Alternatives rejected: individual-Skill scores as environment effectiveness;
LLM self-report as mechanical evidence; a new environment Registry or grader;
and overwriting files still owned by a normal installer.

The official Claude CLI uses a separate explicit restricted-file-tool runtime
kind, rather than reinterpreting the bespoke artificial CLI flags. Exact native
argv, session settings, tool set, model/effort and output schema bind its identity.
Restricted mode confines file tools to working directories; arbitrary execution,
network, MCP, hooks, agents and user config are not enabled. A private empty
config directory and explicitly supplied redacted authentication isolate session
state. Structured stdout is decoded by the harness then re-enters the original
final-output and terminal verifiers. No wrapper executable acquires authority,
no CLI version/help result proves enforcement or quality, and shell evidence
remains unavailable. This bounded native contract can be extended only after
review; enabling shell execution is not implied by workspace-write file access.

Review before additional normal-owner profiles/source migrations, automatic telemetry enablement, unbounded
ambient configuration capture, cross-adapter score pooling, causal attribution,
new-Asset adoption semantics or automatic partial-write recovery.
