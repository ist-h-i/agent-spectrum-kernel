## Connection and trust boundary

`runCoreNativeConnection` composes these boundaries with #324's one shared
receiver. Immutable preparation stays separate; canary and each arm receive a
distinct original task/product copy in new owner-only workspaces. Canary is Full
with its own home/output names, a 10s absolute receive-time cap and 1,000-token
post-trial threshold. It is a wiring/readiness canary, not proof that native tools
performed all filesystem/network controls. Comparison retains 120s startup plus
120s task, 240s absolute, 50,000 per arm and 150,000 cumulative. Token limits are
post-trial stops and can overshoot; they are not spending caps. No restart,
resume, hidden replacement or retry exists, including interrupted/spawn-failed
slots. Slot spending precedes spawn; process-group termination/drain stays 2s.

The closed request binds a unique ID, <=1h expiry, one exact ledger/target root,
Git/source/product/task/evaluator/plan/runtime/roots/launch-map identities,
independent discovery/permission/admission receipt digests and permitted effects.
Source and original preparation are checked before each stage. A native handoff
and successful completion are opaque controller objects: raw candidate receipts,
hashes, approved fields, fabricated canary success and synthetic contexts cannot
mint them or reach production spawn. Failures may be recorded after expiry, but
expiry never permits another start. Ledger identity and every saved receipt are
checked against their controller-held originals before continuation.

Native runtime images are checked only after fresh external authority has been
independently verified. No real image/auth/session path was opened in this work.
The externally pinned runtime/discovery/permission/admission receipts represent
an independent observer's exact-plan attestation. They are not evidence that
this implementation observed actual Skill read/use, host policy or evaluator
independence. These remain Unknown until the independent real-host evidence is
obtained. No authority writer, admission issuer or command that creates a grant
is provided. Existing approvals for older heads/plans are not accepted implicitly.

The new session adapter reuses unique UUID/exact UTC filename probes, owner-only
selected ancestors and no historical listing. All launches now bind `TZ=UTC`.
An explicit 1ms filesystem-mtime tolerance accounts for fractional filesystem
timestamps versus millisecond controller timestamps; legacy callers retain zero
tolerance. UUID, window cardinality, stable no-link reads and session identity
are still required. Streams retain the receiver's 64KiB bound; selected session
and final-message bytes retain bounded readers (session inspected at <=4MiB,
final <=1MiB). Unknown/overflow/missing/unsafe outputs stop continuation.

Each scratch is a newly created `.ask-tmp` mode0700 directory with no ACL, exact
device/inode/owner/mode/birthtime and empty boundaries. No existing chmod occurs.
It is excluded from task-directory equality only at its exact registered path;
remaining files/directories and intervention assets are checked. Native effective
temporary sandbox behavior remains unverified. Final CLI messages and raw
captures are private, create-once, bytes/digest bound. Offline replay requires the
external result digest and checks exact file inventory, original preparation,
source, budget, scratch identity, scope, session/usage/lifecycle and final message;
it never obtains authority, reads auth/session homes, launches or grades.
