# Parent restoration and return to pre-install absence

SPEC/IMP/FVC-PREINSTALL-RETURN-1@1. Upstream: PV1-1/6/7;
SPEC-PERSONAL-TARGET-1@1/@2/@3; bounded target snapshot contract.
This is a human-controlled, initially artificial-only procedure, not a new
production uninstall command, Portfolio transition, automatic repair or retry.
This contract and its artificial drill grant no actual-target execution authority.

## Two different destinations

1. **Improvement rollback**: existing `plan-restore`/`restore` requires current
   separately trusted rollback selection/authority and returns candidate bytes
   to the exact registered parent. Parent five files and personal state/rollback
   remain. It does not uninstall and does not rewind registry/Portfolio history.
2. **Acceptance installation removal**: after verified improvement rollback,
   restore independently recorded pre-install *absence* of the five files and
   personal metadata, while preserving every original entry/byte/mode and Git
   binding. The normal API does not currently perform this successful-install
   removal. Do not use failed-apply recover, generic detach, intentional faults,
   recursive deletion, or forced owner changes as a substitute.

This bounded manual path supports only an initially absent `.agents/` and
`.agent-spectrum-kernel/`, no other installer owner, no target-local recovery
archive, and a healthy registered parent returned through a verified rollback.
Confirm that initial shape from the selected target's independent read-only record;
the presence of this procedure is not proof of completed acceptance.
If directories already existed, contain unknown additions, or an actual recovery
archive was created, stop and prepare a separately reviewed preservation plan.

## U1 — prepare before the first installation

Privately retain outside source/target: canonical root/dev/inode; exact source
revision/identity; successful full-tree initial snapshot with Git HEAD/index;
independent proof that all five paths, personal state and both directory roots
were absent; all actual registered parent/candidate bytes and digests; raw current
plans/confirmations/closure and provenance of independently trusted inputs.
Do not construct an initial absence record from an installed target later. Before
first apply, compare the parent plan's exact target_before binding, target identity
and source identity with that independently pinned initial record. Intervening
worktree/HEAD/index drift stops before any installation; review a new baseline
instead of accepting the changed plan as the old baseline.

The snapshot must meet the reviewed product resource contract. A metadata-size
summary, Git status, tracked-only hashes or an ignored-directory exclusion cannot
replace it. Do not start actual installation before both restoration destinations
have an applicable verified procedure and required inputs.

## U2 — restore and validate the current parent

Use existing independently trusted adoption closure and fresh external Portfolio
rollback authority/selection to execute normal candidate→parent restore first.
Reverify receipt, registered parent projection, current rollback lock and exact
parent five bytes. Require healthy parent state, no Codex lease/other owner,
no marker/journal/foreign lock/recovery archive, no unknown edits or modes.
Immediately after parent bootstrap, privately pin all three newly created directories'
device/inode/mode identities and recheck them after candidate/rollback. Save raw
parent state, prompts, those independent directory pins, exact full-tree
and Git binding outside target, with independent hashes. A saved file is evidence,
not authority. Do not remove a still-installed candidate to bypass rollback.

## U3 — exact reviewed removal record

The operator reviews one removal record bound to U1/U2/source/target pins, genuine
current closure and rollback selection, current full-tree observation, and exact
ordered delta: the five current registered parent files; then the now-empty newly
created `.agents/prompts` and `.agents`; then the exact raw personal state last.
After the shared lock is released, remove only the independently pinned, newly
created, empty `.agent-spectrum-kernel` directory. Preserve the private archive.
No project, Git, global setting, unrelated file, or Portfolio object is deleted.

Check the current request and persistent target-specific authorization. Do not ask
again merely because the phase changed. Execution still requires a concrete
reviewed/confirmed record, satisfied technical inputs, no outstanding actual-write
hold, and any required filesystem approval. Broad
permission supplies neither fabricated evidence nor a missing rollback decision.
Retire the completed operation's prior execution confirmations; archived plans
are not permission to reinstall. No automatic old-plan-replay refusal is promised
once all target-local state is deliberately removed; current caller authority
and fresh exact confirmation remain required.

## U4 — bounded manual execution and partial stop

Acquire the existing exclusive personal-target lock. Reverify the actual caller-trusted
closure/rollback selection before and inside this session; the private archive does
not authenticate it. Revalidate lock/source/target pins and exact full tree inside
the lock. Before **each** action,
recheck the full protected tree and all remaining known endpoints; save an
immutable private write-ahead intent outside target. Each intent binds the prior
phase, exact path/type/bytes/mode, reviewed record and expected after-tree.
Use single-file unlink or empty-directory rmdir only. Immediately before each rmdir,
compare the directory's device/inode/mode with the independently pinned private
record. Same-mode replacement directories are unknown and remain untouched.
Never recursive rm or force.
After each action, verify the exact after-tree and retain a private checkpoint
with raw digest. Personal state remains until the final in-lock step, so a partial
Prompt removal cannot masquerade as a healthy installed state.

An exception/nonempty directory/unknown edit is partial, not complete restoration.
Keep raw archive, intents, checkpoints and any remaining target state. Do not
invoke normal apply/recover/install or remove unknown locks/markers. A human may
continue only after separately reviewing the current exact known partial endpoint,
independently pinned checkpoint and a newly confirmed record for the remaining
suffix. Never infer progress merely from current absence. If failure occurred
between action and checkpoint, preserve the intent plus both possible endpoints
and stop for incident-specific reconciliation; this drill proves only
checkpointed continuation, not automatic gap repair/power-loss recovery.

If state has been removed but final empty metadata directory remains, completion
is still pending: with current exact full-tree validation and pinned directory
identity, remove only that empty directory. New unrelated content stops removal.
Foreign lock/liveness is never overridden. No process termination is inferred.

## U5 — completion proof and limits

After lock release and final directory removal, re-read in a new observation:
exact initial full-tree/Git binding; all five and metadata roots absent; every
original file/mode/dirty artifact unchanged; private raw archive/intent/checkpoint
readback intact. Record actual removed paths and model_runs0. Do not claim runtime
effectiveness, app behavior, model quality or actual acceptance from this drill.
The separately owned temporary test resources are cleaned only after these checks.

FVC obligations: U1 initial absence retained before installation; U2 actual API
parent→candidate→restore on owned fixtures; U3 missing authorization/pin and
unknown edits refuse with no removal; U4 exclusive lock, exact one-path deltas,
checkpointed partial continuation and unknown partial edits stop; U5 exact initial
binding/absence and private evidence readback. Test-only implementations must be
closed to newly owned fixture roots and export no actual-target removal API.
