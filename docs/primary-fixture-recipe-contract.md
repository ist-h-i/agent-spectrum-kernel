# Existing primary fixture command connection

Spec `SPEC-PRIMARY-RECIPE-1` references the owner-approved nine-task preparation,
not an execution grant. The opt-in `ask_primary_fixture_recipe_v1` recipe binds
the existing public task/input manifest, exact native command contract, declared
mutable paths and truthful runner class. It changes neither fixture bytes nor
private grading criteria. Default user-comparison recipes and old plans remain
on their existing fixed Node-test path.

The new model-free `ask-primary-evaluation-prepare.mjs` connector copies only
`task.md + workspace/**` into nine independent Git seeds, then calls the existing
`prepareUserComparison`. Each plan uses `single_shot_v1`, three actual condition
IDs, 60-minute sessions, five-minute checks, four-hour block deadlines and a 5M
reported-token admission budget. Nine plans bind a 48-hour/45M batch manifest.
The original K-principles v1 is preserved and its six missing capabilities remain
blockers. The separately proposed v2 is not silently registered or selected.

The native recipe is closed to these nine existing fixtures. Arbitrary scripts,
changed task/input bytes, extra source files, wider edit scope, substituted task
classes, altered command IDs/scripts/digests, optional/alternative commands and
unknown fixtures refuse preparation. Native commands are the original frozen
`/bin/bash -lc` bytes, run from a fresh `workspace/` verification copy through the
existing direct-child executor. This retains the original shell/global-config
limits; it is not a new sandbox or a claim of identical host environments.

The focused regression task may edit its declared test. This does not weaken the
default fixed-verifier rule: only the closed fixture recipe takes that path.
Original validators, scripts, schemas, specifications and other protected inputs
remain immutable. The docs task exposes a file edit boundary in user-comparison;
the original private evaluator must additionally check its JSON-block-only scope.
Public verification success alone does not prove that task's narrow semantic scope.

Controller receipts preserve command IDs/contract digest/input digest, argv/cwd,
spawn and completion observations, exit status, bounded stdout/stderr/view,
duration and missing/truncated evidence. Native stdout uses `.stdout.log`, not
Node reporter JSONL. An exit-zero native validator establishes structural/public
verification only. Semantic quality remains unknown until the unchanged private
evaluator is connected. Edited model tests cannot declare their own quality.

`ask-primary-evaluation-prepare.mjs /absolute/public-inputs /absolute/options.json`
performs preparation only. `options.json` accepts `output`, `cliBin`, `cliVersion`,
`model`, `reasoning`, `globalAskPresence`, `evidenceKind`; it cannot override
fixture, task, scope, verification or conditions. It refuses existing output and
keeps partial preparation on error. It never launches Codex or consumes start.
Its returned `blocked` record is not executable approval. The production grading
adapter remains blocked while actual condition-schema/normalized authority/private
originals are unavailable. No start CLI is exposed by this preparation entry.

Implementation `IMP-PRIMARY-RECIPE-1` owns the recipe/prepare connector and the
existing preparation/controller seams. No new evaluator, runtime, Skill, authority,
catalog or raw scoring implementation is created.
Formal Verification Contract `FVC-PRIMARY-RECIPE-1` follows
`ask.verification-proof-policy@1.0.0` under
`state_concurrency_persistence_lifecycle_or_cross_module`,
`multiple_specialized_checks`, `multi_session_multi_agent_or_handoff`.
