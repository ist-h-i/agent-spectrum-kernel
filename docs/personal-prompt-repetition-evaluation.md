## Local API sequence

1. Register genuinely source-reviewed parent/candidate Assets in an independent evaluation store, prepare their exact normal candidate and baseline alignment. This module does not create source-review, high-impact, experiment or rollback authority.
2. Author N child normal single-shot experiments and fresh fixed pair preparations, plus a main normal experiment with explicit repetitions=N, `repetitionRecommendationPolicy()` and `canonicalDigest(PROMPT_REPETITION_POLICY)` as its thresholds digest. Freeze every potential lifecycle plan before results. All normal task, output and grading admission contracts still apply.
3. Call `sealPersonalPromptRepetitionPlan` with the main experiment options, the complete ordered `members` array of child experiment/pair object digests, pre-output `rubricDefinitionObjectDigest` and sorted `lifecyclePlanObjectDigests`. Independently review/pin the returned object digest. Preparation is local only; no model is started.
4. A later explicitly authorized normal driver input uses the child experiment/pair plus `repetitionPlanObjectDigest` and `trustedRepetitionPlanObjectDigests`. The driver checks selected-pair membership and verifies the entire fixed plan at preparation and immediately before dispatch, then the normal one-use start writes that binding into its immutable request. There is no automatic multi-pair dispatch.
5. Call `verifyPersonalPromptRepetitionResults` with main options and independently trusted root pins. `savedMembers` may omit missing children; all planned cells remain. Each provided member carries `pairRegistrationObjectDigest`, original `savedResults` and separately established `trustedSavedEngineeringResultDigests`. The verifier never publishes or repairs evidence. Integrity mismatches throw; missing observations hold.
6. Once independently reviewed, a complete auxiliary CAS object supplies all matrix rubric/currency rows, exact original controller-report bindings and shared evaluation overhead. `trustedAuxiliaryReportObjectDigests` must come from an independent provenance check, not from the returned hash itself. Known zeros need actual observations; unknowns remain unknown. Reviewer identity/blinding/currency provenance live in referenced receipts and the caller's trust review; a syntactically complete row cannot authenticate them.
7. Optional `publishPersonalPromptRepetitionProposal` additionally needs exact `trustedEvaluationAuthorities` containing the whole independently reviewed evidence context and a root-fixed `lifecyclePlanObjectDigest` in `trustedLifecyclePlanObjectDigests`. Normal recommendation/action-proposal verification remains required; no human decision, Portfolio transition or target write is performed. A favorable recommendation can support only a bounded canary proposal, not completion of v1 or growth-map acceptance.

The controller binding uses stable run/plan/source/slot/configuration/usage-budget data. It deliberately excludes the derived wall-clock `overall.elapsed_ms`, which changes on readback even after termination. Original controller evidence remains the source; this exclusion never discards slot duration, token usage, failure or outcome.
