## Trust boundary

The producer obtains the read vocabulary from its existing source-owned public
input manifest, checks its exact fixture-input digest and canonical arm root,
and never accepts caller read-path/context overrides. The helper's result is
only an unmatched read. Its words cannot become a public check, cwd witness,
unsafe-action approval, verification reference or proof of isolation. Runtime
command bytes and native started/completed pairing remain the authority.

Unknown commands, paths, scripts and event shapes fail the entire capture.
Successful prefixes/checks are discarded. The existing narrow source-owned V8
unsafe-action positive pairs can survive later capture failure; unknown commands
cannot become new unsafe categories, safety pass, successful verification or
quality0. There is no partial successful verification or invented event.

Exact logical public command bytes, finite Bash/Zsh-lc rendering, status/exit
consistency, no ambiguous check overlap, edits before checks, final snapshot
closure and native terminal turn remain mandatory. Login-shell startup, actual
cwd, OS isolation and resolved model/runtime are not inferred by normalization.
Runtime compatibility remains independently observed or unknown. No new shell,
model, ownership bypass, privilege exception or native qualification is needed
to run these artificial parser/producer/schema tests.
