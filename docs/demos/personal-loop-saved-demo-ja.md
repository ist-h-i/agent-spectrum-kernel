# 保存実績でたどる個人Codex v1の自己改善ループ

2026-11-11更新。このデモは既存の実モデル実行と採用・復旧を説明するもので、読むだけで追加のモデルを起動しません。人間の判断を含む一巡が対象で、完全無人の成功や普遍的な性能改善のデモではありません。

## 1. 改善方針を決める

レビューで「明記されていないことは一切書かない」ではなく、利用者の次の行動に役立つ推奨・参考情報を補足する方針を採用しました。さらに、証拠不足を指摘する際に、関連して既に検証できた動作とその出所も残す候補を作りました。推奨と必須修正を混同せず、同じ説明をSuggestionsへ重複させない変更です。

対象は `skills/review-router/SKILL.md`、`skills/review-ai-quality/SKILL.md`、`docs/review-finding-contract.md`。生成物・回帰テストはその正本に追随します。

## 2. ケースを人間が承認する

簡単なレビュー問題では満点に達して差が測りにくかったため、既存の難問RC01を比較に使用しました。入力、条件、採点基準、モデル設定を固定し、ケース承認後にTerra lowで比較しました。非公開の採点資産を回答側へ渡しません。

## 3. 結果を報告し、人間が採否を決める

| 条件 | RC01の点数 | 経過時間 | 観測input / output token |
| --- | ---: | ---: | ---: |
| 比較元 | 70.5 | 184.679秒 | 685,401 / 7,697 |
| 変更候補 | 76.5 | 775.308秒 | 2,121,233 / 10,200 |

これは一組の観測で、速度改善とは言えません。候補は子エージェント3件、比較元は0件で、候補側には約305秒の説明できない空白もありました。inputにはcacheを含み、完全な請求額とは異なります。人間はこの制約を含む結果を読み、レビュー方針の価値を判断して採用しました。

## 4. 承認した候補を反映する

[PR #491](https://github.com/ist-h-i/agent-spectrum-kernel/pull/491)で正本をmainへ反映しました。実測済み結果から[限定された継続経路](../measured-review-adoption.md)で通常のcontrollerへ引き継ぎ、採用packet、ソース反映、Registry版有効化、所有stagingのcleanup、最終報告まで進めました。

版有効化時にlifecycle authority不足で止まりました。その事実を保存したままホスト支援で復旧し、[PR #492](https://github.com/ist-h-i/agent-spectrum-kernel/pull/492)に事前検査と限定的復旧を追加しました。実測結果や過去の承認を書き換えて正常終了に見せたわけではありません。

## 5. 次のサイクルへ

現在の採用版を次の比較元として固定し、残る課題を次の改善方針にします。[継続・export/import・構成](../instruction-improvement-continuity.md)を使い、次のケースと適用は改めて人間が判断します。前回の採用は次の候補の自動採用を意味しません。

通常の新規候補の生成から進む入口は[標準ループ](../supervised-instruction-loop.md)です。今回の実測済みレビュー候補の引継ぎはRC01と特定のレビュー資産に限定され、任意の過去答案を取り込める汎用機能ではありません。

## このデモから言えること

人間の判断を挟んで、評価結果を実際の変更と版管理へつなぐ一巡を確認しました。候補が必ず勝つこと、処理が一度も止まらないこと、全モデル・全環境で同じ成果が出ることは主張しません。[提供範囲と制約](../personal-v1-release-preparation-ja.md)も確認してください。
