## Implemented synthetic receiver API

`runCoreReceiverSimulation(preparation, preparationDigest, freshResultRoot,
{scenarios:{plain,core,full}, fast:false})` verifies the original model-free
preparation before starting a child. Scenarios come from a closed fixture list;
no executable, argv, grant or shell can be supplied. It starts one fixed Node
child per admitted synthetic slot and stops the next child on any failure.
`fast:true` uses an explicitly recorded 100x synthetic monotonic clock for timeout
tests; it provides no real-time evidence about a host. Normal policy remains
startup120s/task120s/absolute240s, drain2s, retry0. Each stdout/stderr/FD3 channel
is capped at 64KiB; records are capped at 1MiB. Truncated failure bytes and unknown
cleanup are preserved as failed evidence, never accepted as a successful trial.

`replayCoreReceiverResult(root, independentlyKeptResultDigest)` starts no process.
It checks owner-only regular files/directories, no hardlinks/symlinks/extra paths,
source/Node image/preparation identities, original before-state, interventions,
closed receiver/time receipt, capture inspection, sequential stops and usage.
Task edits permitted by the original task scope can be replayed without requiring
an unchanged task input; scope alone provides no semantic score. Preparation and
result digests must be kept independently. Nothing in persisted output grants
execution or changes blocked admission. Existing results are never overwritten.
`runActualCoreNativeReceiver()` always refuses: activation and the actual CLI
session transport remain explicit missing implementation, rather than being
silently satisfied by FD3 synthetic fixtures.

First-stop receive time is retained independently of final drain elapsed time.
Replay reconstructs the event budget at that stop time, preserving a task timeout
when drain later exceeds the absolute cap. Process errors are separate from the
budget stop, so an unknown group-kill error cannot erase a prior timeout or make
the failure record unreplayable. Start attempts and actual direct child starts
are separate counters; replay never treats either as native/model execution.

Synthetic Node processes use the fixed fixture's code boundary, rather than an
actual Codex filesystem/network sandbox. Permission/session rows are deliberately
synthetic and establish parser behavior only. The future Full canary checks the
largest package and common Core; per-condition real discovery receipts are still
required during later trials. Full must discover its local inventory and actually
read/use required task-relevant Skills, not indiscriminately load every Skill.
No extra canaries, fallback trials, authentication probes or diagnostic launches
are implied. Fresh workspace temporary-area protection and exact Node/npm task
command identity are also unresolved native admission items.
