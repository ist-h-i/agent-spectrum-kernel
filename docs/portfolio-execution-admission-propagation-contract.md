# Portfolio execution admission propagation

The existing `--execution-admission-evidence` fixture-keyed manifest accompanies an admitted portfolio plan through `materialize`, `seal-selection`, `verify-selection`, `prepare-execution`, `execute-portfolio`, `verify-execution`, `normalize-execution` and current-source `verify-normalized-results`. The corresponding library options use the existing `executionAdmissionEvidenceByFixture` value. Selection verification immediately before and after an attempt, normalized source reconstruction and terminal workspace reconstruction retain that same evidence input.

Each revalidation resolves the genuine repository-managed overlay and external review authority/archive again, then regenerates the exact plan and compares its source revision, admission set, cases and digest. Missing evidence, changed authority bytes, transplanted fixture evidence, dirty source and a different Git revision remain errors. An already resolved caller admission object does not substitute for the external evidence. No criteria, four-condition protocol, existing end conditions or frozen-source checks are relaxed.

`prepare-execution` exposes the existing ordinary run initializer without resolving an agent executable, loading a runtime configuration, probing a CLI or creating an attempt. Its run directory must be absent or empty; it refuses a nonempty existing run. It saves the original run/case custody records with all cases pending and reports `model_calls: 0`, `case_attempts_created: 0`, `execution_authorized: false`. `preparePortfolioExecution` is the corresponding library API. Preparation does not authorize later execution.

The normal plan's `repository_revision` identifies the actual code checkout; materialization, selection and run identity retain that binding. A source change requires a new plan. A historical root supplied to a current function does not establish execution of historical code. Use an independent fixed code checkout for actual evaluation and preserve its ordinary exact-revision checks.

This controller preparation contract does not grant evaluator processing-source admission. Changing a module in a frozen evaluator dependency graph requires separately reviewed processing/reference/admission bindings with the original criteria preserved. Old evaluator references, private cases, grading records and evaluation snapshots are unchanged by this propagation fix. The private runner is an executable worker program and is never imported or launched by preparation.

Regression: `node scripts/test-ask-benchmark-admission-propagation.mjs` uses a test-only independent Git repository and a synthetic admitted overlay, exercises the existing normal CLI path and verifies all attempts remain empty. `--actual-evidence <manifest>` additionally uses genuine external evidence read-only; it proves controller preparation in the explicitly synthetic source/configuration checkout, not private grading or processing admission. The test's closed command allowlist contains only planning, materialization, selection, preparation, inspection and normalization commands.
