# One-shot installed AppServer catalog probe

SPEC-P24-CATALOG-PROBE-1 / VERIFICATION-P24-CATALOG-PROBE-1 is a formal local
protocol-observation contract following #379/#424. It is not an evaluation
manager or a model/scoring transport. Existing evaluation start/grading guards,
all versions/results and frozen authorities remain unchanged.

- R1: prepare pins the observed0.162.1 native, JS launcher, Node executable,
  resolved platform package and four direct controller source files. Exact plan
  confirmation and re-derivation precede an exclusive owner-only output attempt
  directory. Existing output cannot resume/retry. Source pins are limited local
  controller evidence, not a sealed runtime source closure or admission.
- R2: spawn the pinned Node/launcher with only `app-server --listen stdio://`.
  Use the inherited environment/auth/config and ordinary outer permissions.
  Refuse Node injection variables; do not replace HOME/CODEX_HOME, copy auth,
  configure provider, disable sandbox, install packages or escalate. A fresh
  empty output/workspace is cwd; no task or model instruction is provided.
- R3: exactly initialize(id1), initialized notification, model/list(id2,
  limit100/includeHiddenfalse), gated by ordered valid replies. No config/read,
  thread/turn, task/model call, auth/config/skill/plugin mutation or server-request
  reply. Unknown/duplicate/wrong-order/error/notification stops the probe.
- R4: stdout JSONL is fatal-UTF8/duplicate-key checked; aggregate output2MiB,
  line128KiB, eight lines, controller deadline60s and input64KiB. Only one exact
  already-observed public PATH-alias EPERM warning is recognized; other stderr
  stops. It is not a new exception or a general redaction/permission rule.
- R5: use existing executeCodexSession cancellation and owned process-group
  shutdown; preserve timeout, SIGTERM/SIGKILL escalation and unknown-cleanup
  refusal. Optional onStdinReady provides an expiring bounded synchronous input
  channel. Ordinary fixed-stdin callers retain their existing behavior.
  retainOutputfalse prevents the runner from retaining raw stream buffers.
- R6: the boundary persists only fixed methods/ids/enums, counts, allowlisted
  errno/signal, duration and exact requested model/effort advertised booleans.
  Drop raw stdout/stderr, codexHome/userAgent, account/config/origins, arbitrary
  model metadata/cursor/error text. Unknown or uncertain exit discards advertised
  matches. Absence/hidden/pagination/ambiguity means not_observed, not unsupported.
- R7: the output root contains intent.json, summary.json and empty workspace,
  owner-only and exclusive. No raw log or secret value is saved by the collector.
  Codex itself may use its normal auth/state/cache/log files and background
  communication; the collector does not promise to suppress those existing
  behaviors. Permission/auth/unknown outcomes stop, without retry/alternate path.

The standard generated0.162.1 schema is the protocol reference. The diagnostic
only reports catalog-advertised support for gpt-6.1-sol high/low and gpt-6-luna
max. It does not establish a turn's resolved model, startup effective-input
closure, command cwd, edit lineage, usage/cost, native acceptance or quality.
Runtime attestation remains unknown and scoring authority false in every result.

Model-free verification uses artificial streams and ordinary Node fake servers
(no Codex server/provider): ordering, unknown/auth/tool requests, secrets, byte/
UTF8 framing, EOF, late junk, warning boundary, failed spawn, cleanup uncertainty,
normal/no-retention behavior, deadline and owned descendant termination.
Independent review must precede any live process. A separate explicit live
scope approval is required; the CLI has no automatic escalation/retry route.
This contract does not itself grant that approval or the separate model scope.

Unstarted operation form:
`node scripts/ask-primary-protocol-catalog-probe.mjs run PLAN OUTPUT --confirm PLAN_SHA256`.
The prepare API reads public installation/code bytes only and launches nothing.
The run CLI emits closed summaries on every error, never raw exceptions.
