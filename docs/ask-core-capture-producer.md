# Saved Core capture producer

SPEC-318-CONTROLLER-SCORE-1 revision 2 / IMP-318-CONTROLLER-SCORE-1 revision 2 / FVC-318-CONTROLLER-SCORE-1 revision 2 extend [the controller scoring connection](ask-core-controller-scoring-bridge.md). The bounded delivery includes the generating side: saved capture → derived materialization/selection/run/command/terminal artifacts → the original normalizer → original terminal candidate reconstruction → concrete original private-helper and scorer inputs. This is an additive Core route, not an alias for `kernel_only`, `adaptive_ask` or `full_ask`. Default legacy execution/normalization behavior is preserved. It is not a completed native experiment or support verification.

`produceCoreCaptureArtifacts(input, newOutputRoot)` requires the externally pinned connected normalization, its original saved preparation and final output files, and producer/reviewer direct-stdout records with explicit owner custody acceptance. Original export APIs are optional. A launcher can give `buildCoreDirectControllerRecord` its already saved stdout and actual invocation ID, role, task, source HEAD, capture/request digests, invocation command and times. The owner must establish the actual associations and independent review, not infer them from echoed identifiers or hashes. The closed acceptance states `repository_owner_attested_controller_archive`, no provider signature, and no execution permission. Both record byte digests and raw stdout digests are retained privately. This implementation never invokes that launcher, Codex, a model, authentication stores or an evaluator.

The producer first verifies the existing saved capture/preparation contracts, public product/task bindings, final byte hashes and controller associations. It creates a new owner-only root, copies the saved evidence and exact original materialization bytes, and reconstructs each task terminal snapshot from captured task bytes. Full/Core instructions remain managed assets; grading inputs are not copied into task workspaces. Captured inventories and directories must match, and the existing product auditor rechecks installed profiles. The current fixed task contract does not admit arbitrary additions/deletions: such changes stop at capture normalization instead of being silently reconstructed. An allowed task modification is reconstructed by the original terminal authority/candidate helpers.

Request, result, commit, fixed nonadaptive selection and plan records explicitly identify `saved_core_capture_conversion`; they do not pretend to have been written by the old runner during the trial. Original file-digest semantics, terminal inventory/delta/managed-path checks and normalized source snapshot bindings are retained. Every inspection rederives these records from externally pinned saved capture bytes and rejects even coherently rehashed generated-file changes. It does not rely on marker files alone. The original `normalizePortfolioExecution`, normalized verifier, terminal authority builder/reader and terminal candidate materializer perform the shared calculation/reconstruction. The original scoring root-lineage algorithm checks the resulting raw materialization/selection markers and run identity.

The existing `buildCodexCommandEvidence` parses actual Codex JSONL command events. A completed model turn supplies no missing command observation. Absent, malformed, failed and declined observations remain explicit; they cannot become a passed sealed verification command. Saved token observations feed the original normalizer only inside this capture producer scope; unavailable fields remain unknown. No command is rerun to obtain missing evidence, and no hidden retry exists. Capture time/usage policies remain the separately frozen request's policies and post-trial bounds, including their possible overshoot.

The synchronous producer scope only selects additive condition schemas and the independently reverified generated execution inspection. Its private lifetime state is never returned to callers and is inactive in asynchronous descendants. It cannot supply scoring authority. Native controller scoring additionally binds its journal's producer/reviewer IDs and record digests to this producer's owner-accepted records, includes the complete generated input inventory, and uses the original owner grading context. Synthetic captures/records retain their synthetic realm, including synthetic command events that were emitted without executing commands.

`buildCoreCaptureScoringInputs` verifies the normalizer/root lineage and assembles public frozen grading paths, normalized IDs, original private-helper options, scorer options and the connected producer scope. Missing `privateRoot`, `privateEvaluationRoot`, frozen source root and actual private evaluation artifact paths are reported separately from command failures/missing observations. Paths supplied for later private use are not opened by assembly. `materializeCoreCaptureCandidate` uses the original reconstruction with a fresh separate owner-only output parent. Saved producer replay/assembly remains possible after removing the original preparation/connection/workspace roots and makes no new model calls; it does not reauthenticate native origin or issue admission.

For a future separately authorized private-read step, `createCoreCaptureSealedEvaluatorExecution` verifies public frozen source and the original freeze authority, invokes the existing original private bundle verifier, extracts its actual hidden asset descriptor and calls the original production sealed execution constructor. Unknown/failed/declined required commands or failed capture outcomes stop before private input reads. This API creates inputs for the original worker; it does not execute that worker, generate a substitute evaluator or modify criteria/freeze. Its actual compatibility with the original MN private bundle remains Unknown until the canonical bundle is identified and that exact step is authorized. Private worker invocation, its determinism checks, final evaluation artifacts and fresh trial permissions must be budgeted in the later execution plan.

Formal obligations retain C1–C7 and add P1 direct stdout/capture/request/role/source/owner bindings; P2 exact managed/base/terminal byte reconstruction and immutable source snapshots; P3 original command parser with explicit unknown/failure/decline; P4 original normalizer/terminal/root-lineage integration plus complete input assembly; P5 pure saved replay with private/model/CLI calls excluded; P6 no producer-scope revival, native promotion, condition alias or grading permission; P7 unchanged raw scorer/product/original frozen source/criteria and final independent review/CI. Tests are `node --test scripts/test-ask-core-capture-producer.mjs` plus existing controller/native/receiver/normalizer/scorer regressions. These tests use synthetic Node processes and public fixtures only.

Mac/Linux fake CI and Mac local synthetic checks are platform-independent execution evidence, not completed real-OS model verification. Native Windows ASK entry remains unsupported; WSL entry and Linux/Mac actual trials remain unverified. #291 retains 14 pairs/28 trials and its existing acceptance criteria. #313 remains Draft with its preserved evidence. Common zero-Skill Core was adopted and implemented in #322; this producer does not require a new Core definition.
