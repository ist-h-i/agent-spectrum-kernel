# 通し例：価格改定後に確定見積を再発行する

架空の設計会議を題材にする。以下の業務判断はこの例の前提であり、採用先の承認や実サービスの検証結果ではない。狙いはテストの書き方を見せるだけでなく、テストで区別できる場面が開発の判断をどう変えたかを示すこと。

## 決める前に分かっていたこと

担当者は「見積画面に加えてCSVでも再発行したい」と依頼した。当初案は、二つの出力経路が現在の商品価格から金額を計算するものだった。価格が変わる前なら正しい結果に見える。既存データには見積の参照番号はあるが、過去に確定した金額を裏付ける記録がないものもある。この時点では、値上げ後の再発行で当時の金額と今日の金額のどちらを出すか決まっていない。

| 同じ見積について確かめる場面 | 現在価格でその都度計算 | 確定時の金額を再発行 |
|---|---|---|
| 1,200円で確定し、その直後に表示 | 1,200円 | 1,200円 |
| 商品価格が1,500円になった後に表示・CSV出力 | 1,500円 | 1,200円 |
| 価格改定後に新しい下書きを作成 | 1,500円 | 1,500円 |

二行目を見せて、営業の業務責任者が「確定済みは当時の金額、下書きは現在価格」と決めたものとする。これを要求側の判断とし、版や金額の持ち方は技術側に任せる。テストがこの業務判断を選んだのではない。

## 何を変え、何を変えなかったか

- **責務：** 確定操作がその時点の金額を記録し、画面とCSVは同じ確定記録を読む。現在価格を経路ごとに引く案は、価格改定後の再発行で約束に反するため採らない。商品価格と計算規則の版を保存して再現する案も条件を満たし得るが、必要なのは確定額だけであり、過去の規則を維持する負担が増えるため選ばない。将来、内訳や計算過程の再現まで必要なら方式を見直す。見積を別サービスに切り出す必要はない。
- **着手順：** 帳票の書式を先に増やす計画を改め、先に「確定→価格改定→保存した記録を開き直す→二つの経路で再発行」を確かめる。純粋な金額計算のテストや、二つの出力が互いに一致するだけでは、両方が同じ誤った1,500円を返す場合を除けない。比較の相手は確定時の1,200円とする。
- **公開範囲：** 古い見積に確定額の記録がない場合、「1,500円だった」と推定して出力しない。この例では、営業の業務責任者が「この版では、その見積の確定額が記録から確認できる見積だけを再発行対象とする。確認できない旧見積は、画面・CSVのどちらからも再発行せず、その旨を利用者に示す」と決めた。後日、信頼できる過去の記録を復元できれば対象を見直す。この範囲は公開候補であり、実際の出荷はまだ承認されていない。新規分でも記録を読み戻せない場合、その再発行は公開候補から外して設計に戻す。現在価格を使う下書きまで止める必要はない。

## 後から変える人は何を読むか

[この例の設計判断・作業順・検証義務・レビュー](examples/quote-reissue/decision-record.md)は、要件の決定から同じ仕様IDと版をたどるための実例である。画面・CSVの再発行が確認できても、旧履歴の復元や公開承認の項目には使えないことを、ASK本体の既存の追跡性検査・レビュー判定で確認できる。

仕様 `SPEC-QUOTE-REISSUE` の `AC-CONFIRMED-TOTAL` は二つの利用経路を通して確定額を検証する。`AC-LEGACY-UNAVAILABLE` は根拠のない履歴を確定額として返さない契約、`AC-DRAFT-LIVE-PRICE` は既存の下書きに関する別の契約である。[見積の単体契約](examples/quote-reissue/confirmed-quote.test.mjs)は確定額と現在価格を区別する責務だけを、[保存・再発行の結合テスト](examples/quote-reissue/quote-reissue.test.mjs)は保存後の再読、別ID、複数の利用経路と独立した下書きの挙動を確かめる。単体だけでは保存経路が正しい見積を読み戻すことまでは分からない。実装の選択理由と見直す条件は上記の設計判断に属し、金額の期待値だけを読んでも分からない。採用先では既存の要求・ADR・作業計画にそれぞれ残し、同じ説明を複製しない。

スキルのディレクトリを起点に、Node.js 24の標準機能で確認できる。

```sh
node --test references/examples/quote-reissue/confirmed-quote.test.mjs references/examples/quote-reissue/quote-reissue.test.mjs
```

[確定額を所有するモジュール](examples/quote-reissue/confirmed-quote.mjs)と[保存・再発行の利用経路](examples/quote-reissue/quote-reissue.mjs)を使い、当初案は価格変更後に確定額の契約を満たさず、採用案は一時ファイルを開き直した後の表示・CSVでも契約を満たすことを確かめる。失敗する案を意図的に用意し、その誤りを検出したときに検査が成功する。これはローカルファイルと二つの出力関数に限った実行例であり、実画面、実運用のデータベース、障害時の耐久性、旧データを復元できること、チームやAIの判断能力の向上を証明しない。採用先では実際の保存経路・利用経路で検証してから、その範囲について判断する。
