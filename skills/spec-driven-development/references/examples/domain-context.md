# 架空の予約機能

これは規約を説明する独立したサンプルであり、実プロジェクトの合意や検証証拠ではない。JavaScript版とPython版は同じ仕様を別々に表す。二つを一つの採用先として索引化しない。

- 目的: 確保済みの数量を更新し、呼び出し元へ結果を返す。
- 利用者: 予約処理を呼び出すアプリケーション。
- `capacity`: 確保できる総数。
- `reserved`: 現在確保している数。
- `quantity`: 今回追加したい数。
- 範囲: 単一プロセス内の判断を例示する。永続化、認可、並行更新、通知は扱わない。
- 前提: `capacity`と`reserved`は非負の整数で、`reserved <= capacity`を満たす。JavaScript版では安全に表現できる整数の範囲を使う。この前提を満たす状態の準備・検証はサンプルの対象外とする。
- 合意状態: サンプルの期待値は説明用に固定しているため`accepted`と記す。実際の業務上の決定を意味しない。

観測可能な受入条件は各言語のテストを読む。実プロジェクトで範囲外の性質が必要になったら、受入条件と適切な検証義務を追加する。
