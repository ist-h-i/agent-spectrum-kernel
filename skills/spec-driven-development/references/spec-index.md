# 仕様索引の契約

索引は「何を守るか」「どこを読むか」「何で確かめるか」への案内である。テスト本体やADRを代替せず、索引の存在やリンク数を仕様の完全性の証拠にしない。

## 最小形式

既存の索引やテストランナーのメタデータがあれば再利用する。新しく作る場合の推奨出力は`docs/spec-index.json`。人向けのMarkdown一覧が必要なら同じデータから生成する。

| フィールド | 内容 |
|---|---|
| `format_version` | 索引の形式バージョン。Specのrevisionとは別 |
| `source_fingerprint` | 生成入力のパスと内容を含むハッシュ。索引自身は除外 |
| `source_scope` | 探索対象、除外対象、その理由。対象言語・記法も含む |
| `generator` | 実際に使用した生成コマンドと実装の参照 |
| `items[].spec_ref` | `artifact_id`、`item_id`、`observed_revision` |
| `items[].source` | 正本ファイルと、項目を特定できるアンカーまたはselector |
| `items[].status` | 正本から取得した仕様の合意状態 |
| `items[].lifetime` | 正本から取得した変更寿命 |
| `items[].checks` | 検証のファイル、runner selector、種別。未実装なら空 |
| `items[].gaps` | 未実装・未対応・非自動検証等の具体的な不足 |

必要な項目だけに`context_refs`、`constraint_refs`、`related_spec_refs`、`impact_scope`を追加する。上流依存は正本の`upstream_refs`を参照し、索引側に別の依存関係を手書きしない。関係には「同じ不変条件」「提供・利用する契約」等の理由を付ける。単に近いファイルだからという理由で大量の辺を作らない。

テストの成功・失敗・skip・未実行は、この静的索引へ手入力しない。実行結果は対象revision、環境、コマンド、selectorを持つ別のEvidenceから参照する。

## 生成の手順

1. プロジェクトプロファイルで指定した正本とランナーのテスト一覧を取得する。テストコードを実行しないと探索できないランナーでは、その前提と必要な環境を明示する。
2. テスト近傍の明示的なID・メタデータ、または既存のdecorator/tagを読み取る。AIにテストの意味からIDや合意状態を推測させない。
3. 同じ仕様項目に属する複数ケース・複数レベルのチェックをまとめる。IDの重複自体を禁止せず、正本・revision・意味が矛盾する重複をエラーにする。
4. 非ユニット検証や未実装の受入条件も正本から収集する。対応するcheckがなければ`gaps`へ残す。未対応の記法や探索できないファイルを黙って落とさない。
5. 参照の解決、現在のrevision、runner selectorの一致を確認する。生成入力とジェネレーターをハッシュへ含め、ID・パスで安定して並べる。実行時刻を毎回変化する必須フィールドにしない。
6. `--check`相当では再生成した内容と比較し、古い索引・参照切れ・矛盾を非ゼロ終了で報告する。読み取り検査で追跡対象ファイルを書き換えない。

初期実装では対象言語と採用した記法だけを扱う。汎用の正規表現で全言語のテストを解析できるとは扱わない。実行するチェックの特定にはランナーの正式な探索機能を優先する。ランナー照合ができない項目は、場所への案内としては使えても、自動選択の十分な根拠にしない。

## 完全性の点検

索引内だけの整合性と、要求からの網羅性を別々に確認する。

- **要求 → 受入条件**：決まっている業務ルール、状態遷移、例外、互換性条件に、項目または明示的な未決事項があるか。
- **受入条件 → 検証義務**：適切なレベルの検証か。ユニットテストでは証明できない性質を見落としていないか。
- **検証義務 → 現在の証拠**：今回の対象と環境で実行されたか。skipや古い実行結果を成功に含めていないか。

行・分岐カバレッジ、仕様リンク率、mutation scoreはいずれも補助指標であり、未知の仕様漏れを否定しない。

## 変更時の扱い

ファイル移動やテスト名の変更では索引を再生成し、仕様IDを維持する。仕様の意味が変わったら正本のrevisionを更新し、古い参照の再評価を要求する。失効した仕様やADRは履歴として参照できるが、現在の制約へ自動復帰させない。

索引が古い、生成できない、または対象外がある場合は、その範囲を`Unknown`として正本を直接読む。検証範囲の縮小には使わない。初回セットアップが完了する条件は、実際のコマンドで生成・鮮度検査・参照検査を通し、テスト追加・移動・未対応記法のケースで挙動を確かめること。
